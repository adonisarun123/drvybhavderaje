# Internal linking and relationship structured data

Implements the Monk Mantra *Internal Linking and Structured Data Implementation Guide* (v1.0, 12 Nov 2026) on this site.

## How it works

| Piece | Where | Rule |
|---|---|---|
| In-copy links | `lib/links.tsx` → `TERM_LINKS`, `autolink()` | First mention of a topic links to its page; one link per target per page, three per paragraph, never the page itself. |
| Related Care grid | `lib/links.tsx` → `relatedServicesWithReason()` | Editor's picks (`related` on each page), parent hub, siblings of the same hub, a hub's children. No padding with pages that only share a group. Three to six links per page. |
| `relatedLink` | `lib/seo.ts` → `medicalWebPageJsonLd()` | Added to the existing WebPage node. Only paths the template renders as visible links; the page itself and duplicates are dropped. |
| `significantLink` | same | Not emitted. Pass `significantPaths` only when page-level click data supports it. |
| `isRelatedTo` / `isSimilarTo` | — | Not used. They belong on Service / Product entities; this site describes MedicalProcedure and MedicalCondition entities, and procedures are not marked as similar to one another. |
| Feature flag | `RELATIONSHIP_SCHEMA` | `"false"` removes `relatedLink` / `significantLink` only. Visible links stay. |
| Click measurement | `lib/analytics.ts` → `internal_link_click` | `link_type`: `related` (Related Care grid, child / sibling lists) or `contextual` (links in body copy). |
| Link map | `docs/internal-link-map.csv` | Generated by `npx tsx scripts/link-map.ts` from the same data the pages render. Re-run after any content or link change. |

## Changing a related link

Edit the page's `related` list in `lib/content.ts` or `lib/procedures.ts` (or `seeAlso` in `lib/sub-procedures.ts`), then re-run the link map script. The grid and the structured data both follow. Clinical relationships need the doctor's confirmation; rows marked "doctor to confirm" in the link map are open.

## QA

- `npm test` — unit tests for the link rules and the structured-data flag.
- `E2E_BASE_URL=<site> npx playwright test internal-links` — every declared `relatedLink` is a visible link on the page (read-only).
- After deploy: Schema Markup Validator and Search Console URL Inspection on one page per template.

## Measurement

`relatedLink` is not a ranking factor Google documents. Judge the visible links by `internal_link_click` and enquiries; test the schema separately with the flag, and call any result without a holdout observational.
